# 문서 표기 검사

## 목적과 기준

에이전트나 편집 도구가 바뀌어도 반복되는 문서 표기 위반을 검출한다. 문체 규약은 [작업 흐름 > 문체와 마커](../../docs/workflow.md#문체와-마커)를 따르며, 완료 절차는 [작업 흐름 > 문서 변경 검사](../../docs/workflow.md#문서-변경-검사)를 따른다.

## 실행과 범위

- 저장소 루트에서 `python scripts/check-docs.py`를 실행한다.
- Git이 추적하는 파일과 무시하지 않는 새 파일 중 `.md` 파일을 검사한다. 삭제한 파일은 제외한다.
- 별도 파일을 확인할 때는 `python scripts/check-docs.py 경로`로 실행한다.
- Python 3.12 이상의 표준 라이브러리와 Git을 사용한다. 외부 서비스나 모델 호출은 사용하지 않는다.
- 헤더와 구분 행을 갖춘 일반 Markdown 파이프 표를 검사한다. 바깥쪽 파이프 생략과 이스케이프한 파이프를 지원한다.
- 코드 블록과 인라인 코드는 검사 대상에서 제외한다. 링크는 화면에 표시되는 이름을 검사한다.
- 인용문·목록 안의 중첩 표, HTML 표, 한국어 문법 전체와 같은 열의 의미적 일관성은 자동 판정하지 않는다.

## 오류와 출력

코드 형식과 발급·유지 규칙은 [기술 방향 > 진단 코드](../../docs/engineering/strategy.md#진단-코드)를 따른다. 이 검사기는 `DOC` 영역을 사용한다.

| 오류 코드 | 검출 대상 | 수정 방향 |
| --- | --- | --- |
| DOC001 | 표 셀 끝의 마침표·물음표·느낌표 | 명사구 표현과 끝 구두점 생략 |
| DOC002 | 표 셀 끝의 지정된 서술형·명사형 종결 표현 | 상태·성질·행위의 명사구 표현 |

DOC002는 기존 검사 대상이었던 여섯 서술어를 현재·과거, 명사형·한다체·합니다체의 조합으로 검사한다. 모든 한국어 서술어를 판별하는 문법 검사기는 아니며, 아래 범위 밖의 표현은 문체 검토에서 확인한다.

행은 서술어명 가나다순으로 정렬한다. 열은 현재·과거 순서로 묶고, 각 시제 안에서 명사형·한다체·합니다체 순서로 배열한다. 이 표는 서술어별 검사 범위를 조회하는 표이며, 행 사이에 의미상 대립 관계를 부여하지 않는다.

| 서술어 | 현재 명사형 | 현재 한다체 | 현재 합니다체 | 과거 명사형 | 과거 한다체 | 과거 합니다체 |
| --- | --- | --- | --- | --- | --- | --- |
| `되다` | `됨` | `된다` | `됩니다` | `되었음` / `됐음` | `되었다` / `됐다` | `되었습니다` / `됐습니다` |
| `않다` | `않음` | `않는다` | `않습니다` | `않았음` | `않았다` | `않았습니다` |
| `없다` | `없음` | `없다` | `없습니다` | `없었음` | `없었다` | `없었습니다` |
| `이다` | `임` | `이다` | `입니다` | `이었음` / `였음` | `이었다` / `였다` | `이었습니다` / `였습니다` |
| `있다` | `있음` | `있다` | `있습니다` | `있었음` | `있었다` | `있었습니다` |
| `하다` | `함` | `한다` | `합니다` | `하였음` / `했음` | `하였다` / `했다` | `하였습니다` / `했습니다` |

같은 칸의 여러 표현은 축약형이나 앞말에 따른 형태 차이다. 실제 형태가 다른 경우 문자열 수를 맞추지 않는다. `않다`는 동작의 부정을 기준으로 한다. 형용사 부정의 `않다` 종결과 해요체·높임·미래 등의 표현은 이 검사 범위에 포함하지 않는다.

다음 형태는 셀 전체이거나 바로 앞에 공백이 있을 때만 검출한다. 위 검사 범위 표의 행·열 순서로 나열한다.

| 서술어 | 경계 조건 적용 형태 | 붙여 쓴 별도 검토 대상 |
| --- | --- | --- |
| `되다` | `됨` | `완료됨` |
| `이다` | `임` | `후보임` |
| `이다` | `이다` | `후보이다` |
| `하다` | `함` | `허용함` |

한 글자 형태와 `이다`를 다른 단어의 끝에서 찾으면 `책임`·`사이다`·`결함` 같은 명사까지 검출할 수 있어 경계를 제한한다. 위 표의 붙여 쓴 표현은 문체 검토에서 확인한다. 나머지 형태는 셀 끝의 문자열로 검출한다.

[문서 검사기](../../scripts/check-docs.py)의 `PREDICATE_FORMS`는 위 서술어·시제·표현형 표와 같은 행·열 순서를 사용한다. 칸이 누락되면 검사기 초기화가 실패한다. 회귀 테스트는 실제 문장에 각 형태를 적용해 검출 여부를 확인하며, 정상 명사의 오탐도 함께 검사한다.

표현형별 테스트 데이터는 한 표현형을 한 줄에 두고 현재 세 줄, 과거 세 줄 순서로 작성한다. 같은 표현형의 대안은 같은 항목에 둔다. 이 줄바꿈은 차원 구분을 위한 배치이며, 파일 전체의 코드 포맷 규칙을 새로 정하지 않는다.

| 종료 코드 | 판정 | 출력 |
| --- | --- | --- |
| `0` | 검출된 위반 부재 | 검사 파일 수 |
| `1` | 표기 위반 검출 | 파일·줄·열·오류 코드·수정 방향 |
| `2` | 검사 실행 실패 | 파일 읽기·Git 실행 등의 오류 원인 |

## 자동 실행

[문서 검사 워크플로](../../.github/workflows/docs-check.yml)는 push와 pull request에서 검사기 회귀 테스트와 문서 검사를 실행한다. 별도의 문서 경로 필터를 두지 않는다.

워크플로 파일 추가만으로 병합이 차단되지는 않는다. 원격에서 워크플로가 실행되는지 확인하고, 저장소의 보호 규칙에서 해당 검사를 필수 검사로 지정해야 병합 조건이 된다. 이 설정과 원격 실행 결과는 별도로 확인한다.

## 수용 기준과 확인 방법

| 수용 기준 | 확인 방법 |
| --- | --- |
| 진단 코드 형식과 명세·구현 등록의 일치 | 코드 형식·등록 목록 테스트 |
| 기존 색상 초안의 위반 종결 표현 검출 | 실제 위반 문구의 회귀 테스트 |
| 서술어·시제·표현형 조합의 검출 범위 충족 | 조합별 실제 문장과 축약형 테스트 |
| 정상 명사구·코드·경로의 오탐 방지 | 정상 문구와 코드 예제 테스트 |
| 표 헤더·본문의 동일 규칙 적용 | 헤더와 본문별 위반 테스트 |
| 코드 블록·이스케이프 파이프·링크 처리의 정확성 | Markdown 경계 사례 테스트 |
| 위반 위치와 실패 종료 코드 제공 | 임시 파일을 사용한 명령 실행 테스트 |
| 추적 파일과 새 문서의 검사 포함 | 임시 Git 저장소를 사용한 파일 탐색 테스트 |

자동 검사 결과와 별도로 작성자가 변경 문서의 문체와 의미를 검토한다. 이 검토는 에이전트의 기억이나 대화 기록에만 의존하지 않고 공통 작업 흐름에서 요구한다.

예시와 테스트 데이터는 [작업 흐름 > 예시와 테스트 데이터](../../docs/workflow.md#예시와-테스트-데이터)를 따른다. 실제 오류 사례는 원문과 수정문을 짝지어 보존한다. 검사 범위의 누락은 서술어·시제·표현형의 조합으로 확인한다.
