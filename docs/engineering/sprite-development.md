# 2D 스프라이트 개발 계획

상태: 초안

## 목적과 범위

EPOCA에서 사용할 2D 스프라이트 제작·실행 방식을 검토한다. 기존 도구 조사, 공통 개념과 요구사항 정의, 비교 실험, 게임 적용의 순서로 진행한다. 자체 도구 개발과 오픈소스 공개 여부는 기존 도구로 충족할 수 있는 범위와 추가 기능의 효과를 확인한 뒤 결정한다.

시각 방향은 [게임 설계 > 시각 표현](../game/design.md#시각-표현)의 고품질 픽셀 아트다. 세부 화풍·기준 해상도·시점·방향 수·게임 엔진·적응 수치는 미정이다. 게임 규칙은 [게임 설계](../game/design.md)와 [미결정 사항](../game/open-questions.md)을 따른다. 실험에 필요한 선택은 가정으로 표시한다. 이전 탐색의 문서·코드·이미지는 재사용하지 않는다.

초기 실험에서는 다음을 공통 가정으로 사용한다. 각 실험 계획에서 구체적인 값을 고정하고, 가정 자체를 비교할 때는 변경 변수를 명시한다. 이 가정으로 게임 규칙을 확정하지 않는다.

- 측면 시점에서 한 방향을 제작하고 좌우 반전으로 반대 방향을 표시한다.
- 사냥 화면에는 무리 단위의 소수 개체를 표시하고, 같은 개체 그래픽을 배경에도 재사용한다.

좌우 반전 시 비대칭 외형·공격 방향·피벗·이벤트 위치가 의도대로 표시되는지 확인한다. 화면의 전투 개체 수와 배경 개체 수, 서로 다른 변종 수를 구분해 기록한다. 소수 개체 조건의 성능 결과를 더 많은 개체가 표시되는 조건으로 일반화하지 않는다.

## 게임 설계에서 받는 입력

[게임 설계 > 적응 정보와 튜토리얼](../game/design.md#적응-정보와-튜토리얼)에 따라 외형은 적응 변화에 맞춰 단계적으로 바뀌며 현재 적응 상태를 전달해야 한다. 표현해야 할 외형 상태의 수는 적응별 단계 수, 동시에 나타날 수 있는 적응의 조합, 기존 적응의 교체 방식에 따라 산정한다. 외형 상태 수와 실제 제작할 에셋 수는 파츠·동작 공유 방식에 따라 다를 수 있다. 단계·임계값·조합·교체 방식과 약해진 적응의 외형 처리는 [미결정 사항 > 적응](../game/open-questions.md#적응)에서 관리한다.

적응은 외형뿐 아니라 자세·이동 방식도 바꿀 수 있다. 외형만 바뀌는 경우에도 기존 동작의 재사용 가능성을 검증하며, 자세·이동이 바뀌는 경우에는 기존 동작 조정과 신규 제작의 범위를 확인한다. 두 경우의 제작 비용과 검증 기준을 구분하고, 재사용·수정·신규 제작에 든 작업을 각각 기록한다.

## 기존 도구 조사

[2D 스프라이트 도구 조사](../../research/sprite-tools/plan.md)는 각 도구의 목적·제공 기능·입출력·구현·검증 방식에 대한 근거를 수집한다. 기능이 다른 도구는 담당 작업으로 구분한다. 생물 분류나 EPOCA의 적응 규칙을 기존 도구의 공통 평가 기준으로 넣지 않는다.

조사 결과로 기존 기술의 지원 범위를 먼저 확인한다. 우리 요구를 충족하지 않는 부분은 요구사항과의 차이로 기록한다. 그것만으로 기존 도구의 품질이 낮거나 새 오픈소스의 가치가 입증됐다고 판단하지 않는다.

첫 조사에서는 선정한 8개 저장소의 고정 버전 분석을 완료했다. [2D 스프라이트 도구 비교](../../research/sprite-tools/report.md)에 담당 기능·검사의 보장 범위·재사용 후보·후속 실험 질문을 정리했다. 개체별 안내와 수정 반복의 기존 구현을 확인했으며 사족보행 탐지·적응 외형·실제 출력 품질은 미검증이다. 리그 제작 도구와 베이크 경로는 해당 실험 계획 전에 추가 조사한다.

## 개념과 출력 계약

공통 용어와 표현 방식의 설명은 `docs/engineering/sprite-concepts.md`, 채택할 입출력과 수용 기준은 `specs/sprite-assets/spec.md`에서 정의할 예정이다. 해당 단계에서 근거와 내용을 작성할 때 파일을 만들며, 이 계획은 작업 순서와 미검증 가설을 관리한다. 실험별 가정·입력·평가 기준은 해당 실험 계획에 둔다.

실험 전에 다음 항목을 정의한다. 생성·편집·배포·실행 단계의 표현과 비용을 구별한다.

- 원화·스프라이트·프레임·시퀀스·스프라이트 시트·텍스처 아틀라스·리그·영상의 의미와 제작 경로별 입출력을 정의한다. 기술 용어는 확인한 공식 문서의 명칭과 연결한다.
- 프레임 크기·원점·피벗·트림·패딩·방향·시간·루프·이벤트·상태 전환을 출력 계약으로 검토한다. 알파·반투명 가장자리·리샘플링·색 공간·프레임 순서의 처리와 검사 기준도 정의한다.
- 제작 형식과 실행 형식을 구분한다. 리그로 제작한 동작을 내보내기·빌드 단계에서 프레임 이미지로 미리 렌더링하는 베이크(bake)처럼 두 형식이 다를 수 있다. 각 도구가 지원하는 변환 경로와 제약을 확인하고 제작 형식만으로 실행 형식을 확정하지 않는다.
- 생성 원본·편집 중간물·배포 파일·실행 중 텍스처를 구분한다. PNG·WebP 등 파일 형식의 사용 방식과 무손실·손실·알파·지원 환경을 조사한다. 특정 인코딩의 파일 크기만으로 실행 중 메모리나 동작 품질을 판단하지 않는다.
- 아틀라스 패킹·개별 파일·해상도·색상 수·텍스처 압축·캐시·지연 로드·공유·해제의 최적화 후보와 평가 조건을 정한다.

## 외형 변화의 인지 기준

변종 생성의 효과를 비교하기 전에 표시 조건별 외형 변화의 인지 기준을 확인한다. 변경 부위·색·무늬·실루엣 등의 변화 수준과 표시 크기·배경·동시 개체 수·제시 시간을 실험 계획에서 정의한다. 실험한 수준 중 사전에 정한 인지율·오인율·응답 시간 기준을 충족하는 최소 수준을 찾으며, 기준을 충족하지 못하면 그 결과를 기록한다. 서로 다른 변화 유형을 하나의 변화량으로 취급하거나 한 조건의 결과를 모든 대상에 적용하지 않는다. 실험 방법과 측정 항목은 [게임 검증 > 플레이 경험](../game/validation.md#플레이-경험)을 따른다.

인지 실험은 직접 그리거나 편집한 정적 이미지로 먼저 수행할 수 있다. 정적 이미지의 결과는 재생 중인 동작과 실제 사냥 화면에서 다시 확인한다. 변화의 발견과 현재 적응 상태의 이해를 구분하고, 생성 품질과 인지 기준을 한 실험에서 함께 판정하지 않는다. 이 기준은 변종 생성 평가의 입력이며 도구 조사나 형식·성능 실험 전체를 시작하기 위한 선행 조건은 아니다.

## 비교 평가

평가는 기존 도구의 재현 가능한 기준선, 구성 요소별 변경 효과, EPOCA 적용 결과로 구분한다. 서로 다른 작업을 수행하는 도구에 같은 합격 기준을 강요하지 않는다. 같은 작업의 대안을 비교할 때 입력·평가·자원 조건을 맞춘다.

- 생성 경로는 자연어에서 단일 객체를 만든 뒤 동작을 생성하는 방식, 참조 이미지 기반 생성, 시트 직접 생성, 영상의 프레임 추출, 리그·파츠를 이용하는 방식으로 나누어 검토한다. 경로 전체의 비교와 요소 하나의 적용 유무 비교를 구별한다.
- 리그 기반 제작과 프레임 기반 제작은 모두 비교할 수 있는 최소 규모의 파이프라인을 구성한다. 제작 방식의 비교와 실행 형식의 비교를 나누며, 지원되는 경우 같은 리그 동작의 실시간 재생과 베이크한 프레임 재생을 비교한다. 비교 대상·예산·중단 조건은 실행 전에 정하고, 파이프라인 구성과 대량 제작에 쓸 방식의 채택은 별도로 판단한다.
- 품질은 동일 개체 인상·비율·색·무늬·크기·알파·크롭·정렬의 일관성과 동작의 연속성·루프 연결을 평가한다. 대상과 동작에 적용되는 경우 관절·접지·발 미끄러짐·돌발 움직임도 확인한다. 변종은 [2D 스프라이트 개발 계획 > 외형 변화의 인지 기준](#외형-변화의-인지-기준)을 해당 표시 조건에서 충족하는지 확인한다.
- 실행 성능은 파일 크기·전송·첫 로드·사용 가능 시각·디코드·업로드·메모리·프레임 시간·입력 반응으로 구분한다. Lighthouse와 지속 게임 재생의 측정을 분리한다. 기기·동시 개체 수·서로 다른 변형 수·재진입 조건을 포함한다. 리그 실행·베이크한 시트 실행 등 실행 형식별로 측정한다.
- 운영 비용은 반복 생성 편차·전체 실패율·재시도·사람의 수정 시간·성공당 비용으로 측정한다. 평가의 오탐·누락·검토자 불일치도 확인하고, 평가기를 조정한 사례와 최종 평가 사례를 분리한다. 초기 제작 환경 구성 비용과 변종 하나의 추가 비용을 구분하며, 추가 비용은 외형만 바뀌는 경우와 자세·이동이 바뀌는 경우로 나눠 측정한다.

픽스처는 입력 조건을 고정하는 자료다. 생성 결과를 보존했다는 이유만으로 정상 품질의 기준으로 삼지 않는다. 입력·도구·모델·생성 지침·시각·환경·산출물·측정을 연결하는 실험 기록은 [기술 조사 및 실험 지침](research.md)을 따른다.

## 추가 기능의 가설 검증

다음은 구현이 확정된 기능이 아니라 효과를 확인할 가설이다. 기존 도구에서 이미 해결하는지 조사하고, 남는 질문만 실험으로 검증한다. 생물을 대상으로 하는 가설의 결과를 모든 스프라이트에 일반화하지 않는다.

- 입력 대상의 몸 구조·이동 방식·지지 부위·공격 수단·역할을 분류하면 동작 선택과 생성 품질이 개선되는지 확인한다. 분류의 정확성과 생성에 주는 효과를 구분한다.
- 대기·이동·공격·피격 등 필요한 동작을 선택하고, 생물 특성별 생성 지침을 적용했을 때 자연스러움이 개선되는지 확인한다. 적용하지 않는 동작과 대상은 이유를 기록한다.
- 동작의 이상을 탐지하는 평가가 실제 어색함을 포착하는지 확인한다. 자동 지표와 사람의 판정을 비교하고 오류 유형별 오탐·누락을 분석한다.
- 국소 변경·보호 영역·변화 강도·누적 편집을 통제하면 같은 개체라는 인상을 유지하면서 외형 변화를 전달할 수 있는지 확인한다. 외형만 바꾸는 경우와 자세·이동까지 바꾸는 경우를 구별한다.
- 몸 구조가 같은 개체가 리그와 기본 동작을 공유하면 변종 추가 비용이 줄어드는지 확인한다. 공유한 동작의 자연스러움이 개체별로 유지되는지도 함께 확인한다.
- 자세·이동까지 바꾸는 변화가 외형만 바꾸는 변화보다 인지 효과가 커서 추가 제작 비용과 실패율을 감수할 만한지 확인한다. 인지 효과는 [게임 검증 > 플레이 경험](../game/validation.md#플레이-경험)의 표현 조건별 비교 결과를 사용한다.
- 평가 결과에 따른 수정·재생성으로 성공률과 비용이 개선되는지 확인한다. 통과·규칙 위반·검사 오류·미검증에 대한 다음 행동, 재시도 한도와 중단·사람 판단 요청 조건을 정한다.

기준선·기존 도구 적용·자체 변경 적용을 비교하고, 전체 구성과 개별 변경의 효과를 구별한다. 실험 질문·조건·반복·예산·중단·판정 기준을 실행 전에 확정한다. 이 단계의 결과로 자체 개발의 필요성과 적용 범위를 판단한다.

## EPOCA 적용 검증

게임의 적응 규칙에 따른 외형 변화가 실제 표시 크기에서 인지되는지 확인한다. 같은 개체라는 인상, 행동·이동 코드와 애니메이션의 연결, 이동 속도·공격 판정·피격·상태 전환, 동시 개체와 변형 수에 따른 실행 비용을 함께 검증한다.

이 검증은 EPOCA의 요구에 대한 적합성 평가다. 범용 도구의 기능·품질 평가 및 추가 기능의 효과 검증과 결과를 구분한다. 미결정 게임 규칙은 실험 결과만으로 확정하지 않는다.

## 진행 상태

다음 작업은 픽셀 아트 기준의 첫 비교 실험 계획이다. 새 작업 브랜치에서 아래 순서로 진행한다. 조사에서 남긴 질문과 공백은 해당 계약·실험의 선행 조건으로 연결한다. 문서 작성이나 형식 검사 통과를 실행·품질 검증의 완료로 간주하지 않는다.

1. 사용자와 기준 해상도·고정 입력·첫 비교 도구·생성 예산을 결정한다. 개념·출력 계약·평가 기준은 첫 비교에 필요한 범위부터 정의한다.
2. 같은 생성 원본에 최소 분할·표시만 수행한 조건과 기존 오픈소스 후처리를 적용한 조건을 비교한다. 최소 처리의 범위를 명시하고 생성 편차를 후처리 효과에 섞지 않는다.
3. 생성 지침을 비교할 때는 기준 이미지·생성 도구·출력 조건·후처리를 고정한다. 기존 도구의 지침 효과를 먼저 확인한 뒤 자체 지침을 하나씩 추가한다.
4. 원본과 후처리 결과를 분리해 보존하고 프레임별 크기·위치 변동을 확인한다. 반복 횟수와 실패 처리 방식을 실행 전에 정한다.
5. HTML에는 비교 질문·조건 차이·A/B 재생과 최소 조작만 표시한다. 상세 지침·출처·실행 기록은 링크로 연결한다.
