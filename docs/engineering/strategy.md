# 기술 방향

## 서버

- 전투·보상·거래·적응 등 결과에 영향을 주는 계산은 서버가 처리한다.
- 접속 유지 여부에 따른 보상은 [게임 설계 > 접속과 미접속 보상](../game/design.md#접속과-미접속-보상)을 따른다.

## 그래픽과 진입 화면

- 게임 그래픽은 2D로 제작한다. 캐릭터와 몬스터의 애니메이션 제작 도구 및 실행 방식은 구현 설계에서 정한다.
- 게임 진입 화면에는 WebM 애니메이션을 사용한다.
- 진입 화면의 시각적 참고 자료는 README에 사용한 [EPOCA 헤더 이미지](../assets/epoca-header.png)다. 하늘의 부유 지형, 양쪽의 유적과 절벽, 수면 아래 생태, 따뜻한 수평선과 푸른 바다의 분위기를 살린다.
- 진입 화면용 원화와 영상은 대상 화면의 비율·해상도에 맞춰 별도로 제작한다. 영상 길이·프레임률·용량, 반복 재생의 연결, 재생 실패 시 대체 화면과 지원 기기는 구현 설계에서 정한다.

## 에이전트 하네스

하네스는 에이전트가 문맥을 읽고, 도구를 실행하고, 결과를 관찰·검증하는 작업 환경이다. 하네스 개발에도 [작업 흐름](../workflow.md)을 적용한다.

### 규칙과 퓨샷

- 퓨샷은 실제 작업에서 관찰한 사례로 구성한다. 원래 입력·출력과 수정 결과를 함께 남기고, 관련 문서·실험 기록·변경 이력 등 출처를 연결한다.
- 퓨샷의 문구와 상황을 대칭에 맞추기 위해 바꾸지 않는다. 규칙의 검증을 위해 만든 합성 사례는 실제 사례와 구분한다.
- 규칙은 대상·조건·결과 등 독립적인 차원을 먼저 정하고, 각 차원의 값과 적용 가능한 조합으로 정의한다. 관찰한 표현을 단순히 나열한 목록을 전체 규칙으로 간주하지 않는다.
- 차원별 대응 관계로 누락을 확인한다. 적용하지 않는 조합은 이유를 명시하고, 실제 변형 수가 다른 항목의 개수를 억지로 맞추지 않는다.
- 차원과 값의 배열 순서는 [작업 흐름 > 작성 기준](../workflow.md#작성-기준)에 따라 목록 전체에 적용한다. 기존 표의 일부 항목을 설명하거나 시험하는 자료도 원래 행·열 순서를 유지한다.
- 검증은 실제 사례의 재현과 차원별 적용 범위 확인을 함께 포함한다. 출처·차원·제외 사유·배열 기준을 검토한 뒤 완료를 판단한다.

### 진단 코드

- 하네스가 출력하는 진단 코드는 영역 접두어와 영역 내 번호로 구성한다. 접두어는 영문 대문자 세 글자, 번호는 `001`부터 `999`까지 세 자리로 표기하고 구분자는 사용하지 않는다.
- 접두어는 검사 영역의 의미를 드러내는 약어로 정하고 아래 목록에 등록한다. 이름의 앞 세 글자를 자동으로 잘라 사용하지 않는다.
- 번호는 영역 안에서 처음 등록하는 순서로 부여한다. 번호에 심각도나 실행 순서의 의미를 넣지 않는다.
- 발급한 코드의 의미를 유지한다. 문서나 실행 순서를 바꿀 때 번호를 다시 매기지 않으며, 폐기한 번호를 다른 의미로 재사용하지 않는다. 폐기 상태는 해당 기능 명세에 남긴다.
- 영역 목록은 접두어순, 영역별 진단 목록은 번호순으로 정렬한다. 코드 형식과 명세·구현의 등록 일치는 각 검사기의 테스트에서 확인한다.

| 접두어 | 영문명 | 검사 영역 | 기준 문서 |
| --- | --- | --- | --- |
| `DOC` | Documentation | 문서 표기 | [문서 표기 검사](../../specs/docs-style/spec.md) |

### 역할

| 용어 | 역할 | 예 |
| --- | --- | --- |
| Guide | 작업 기준과 사용 방법 안내 | `AGENTS.md`, 명세, 도구 설명 |
| Sensor | 실행 상태와 결과 관찰 | 로그, 메트릭, 트레이스, 화면 |
| Verification | 명세·수용 기준 충족 여부 확인 | 테스트, 정적 검사, 시나리오 검증 |
| Gate | 판정 결과에 따른 다음 동작의 허용·차단 | 필수 CI 검사, 배포 조건 |
| Eval | 작업 사례 집합에 대한 기준별 성능 평가 | 성공률·정확성·시간·비용 비교 |

같은 도구가 여러 역할을 맡을 수 있다. 테스트는 Verification을 수행하고 결과를 Sensor로 제공할 수 있다. 그 결과가 실제 병합 조건에 연결되면 Gate로도 작동한다. Eval 결과 역시 기준을 정해 Gate에 연결할 수 있다.

### 명세 항목

- 대상 작업과 막아야 할 실패
- 제공할 문맥·도구·실행 권한
- 관찰 신호, 검사 기준, 결과 전달 경로
- 실행 환경의 격리·초기화·재현 방법
- Gate의 적용 위치와 실패·미실행 시 처리
- Eval의 사례·채점 기준·비교 조건·비용 측정

관찰·검증·차단의 적용 여부는 실제 코드와 설정으로 확인한다.
