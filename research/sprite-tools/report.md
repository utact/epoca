## 조사 범위

[2D 스프라이트 도구 조사](plan.md)에서 선정한 8개 저장소의 첫 분석을 완료했다. 생성·편집·이미지 처리·패킹·프레임 재생·리그 재생을 포함한다. 원본 저장소의 목적과 기본 브랜치의 고정 커밋을 기준으로 문서·코드·일부 테스트·CI 정의를 확인했다. 스타 수·보관 상태·마지막 커밋 시각과 주장별 링크는 개별 분석에 기록했다.

범용 생성 기반인 ComfyUI·AnimateDiff와 편집 대안인 LibreSprite·Aseprite는 계획에 보류 이유를 남겼다. 영상 디코더 내부·리그 제작 편집기 전체·생성 모델 전체는 분석하지 않았다. Sprute의 낮은 인지도는 숨기지 않고 템플릿 기반 경로의 대조 목적으로 포함했다. 이번 후보가 전체 생태계를 대표하거나 최선의 도구라고 판단하지 않는다.

도구 설치·모델 다운로드·이미지 생성·브라우저 재생·성능 측정은 수행하지 않았다. 아래 결과는 코드와 문서의 분석이며 실제 산출물의 품질 순위가 아니다. 테스트 정의·CI 호출의 존재와 실행 성공·필수 병합 조건을 구분한다.

## 비교 결과

### 담당 기능과 입출력

아래 표는 생성·편집·처리·출력·재생 순서다. 다른 역할의 도구는 대체재가 아니라 조합할 구성 요소로 비교한다. 생성 도구도 설정·제공자·모델·구동 모션이 달라 공통 입력을 맞춘 실행 전에는 우열을 판단할 수 없다.

### 검사와 판정의 경계

생물별 안내와 수정 반복은 이미 일부 도구에 있다. 이 아이디어의 존재 자체를 새 오픈소스의 차별점으로 삼기 어렵다. 반면 확인한 코드만으로 사족보행의 자연스러움이나 EPOCA의 외형 적응 요구가 해결됐다고 판단할 수도 없다.

## 재사용 후보

아래 순서는 출력 계약·후처리·관측·생성 제어다. 코드 복사나 패키지 도입을 확정한 목록이 아니며 API 사용·어댑터 작성·알고리즘 참고를 후속 설계에서 구분한다.

1. 패커와 PixiJS의 원본 크기·트리밍 오프셋·회전·앵커 표현을 공통 출력 계약의 근거로 사용한다. 프레임 순서·지속 시간·동작 이벤트는 별도 계약으로 연결한다.
2. rembg의 마스크·가장자리 처리 분리와 sprite-gen의 후처리 경로를 구성 요소 비교의 후보로 둔다. 패킹·인코딩 최적화는 시각 품질 검사 이후에도 원본과 비교할 수 있도록 파생물로 보존한다.
3. sprite-gen의 접지 측정과 수정 반복 기록을 관측 설계의 후보로 둔다. Sprite Studio의 검사 적용 조건·출력 차단 경로·검토 상태도 비교하되 검사 부재를 합격으로 합치지 않는다.
4. 상태별 시트·영상·리그·구동 모션 경로를 생성 대조군으로 유지한다. 같은 입력으로 각 경로를 준비하는 시간과 실패를 포함해 비용을 계산한다. 경로 전체 비교와 한 지침·처리 단계의 적용 유무 비교를 분리한다.

현시점의 권고는 공통 출력·관측 인터페이스를 먼저 정의하고 기존 구성 요소로 기준선을 만드는 것이다. 자체 생성기부터 구현할 근거는 아직 없다. 새 기능의 후보 가치는 다양한 신체 구조와 외형 변화에서의 실패 탐지·수정 효과를 재현 가능한 비교로 입증하는 데 있다. 이는 조사로부터의 개발 가설이며 검증 결과가 아니다.

## 미확인 사항

다음 항목은 미완료 실행이며 도구의 결함 판정이 아니다. 기존 계획의 전체 실험 범위를 대체하지 않고 후속 계획에서 구체화할 질문을 정리한다.

| 질문 | 비교와 관측 | 선행 조건 |
| --- | --- | --- |
| 생성 경로별 일관성과 비용 | 시트·영상·리그·구동 모션의 품질과 전체 실패율·성공당 비용 | 공통 입력·출력 어댑터·실행 예산 |

| 프레임과 상태 사이의 연결 | 루프 경계와 대기·이동·공격·피격 전환·이벤트 시점 | 동작별 반복 정책·상태 전환 계약 |

Lighthouse 점수와 지속 재생 중 프레임 시간을 같은 성능 지표로 취급하지 않는다. 파일 용량 감소가 동일 개체 인상·관절 동작·접지의 개선을 뜻하지도 않는다. 리그 제작 도구와 베이크 경로는 현재 조사에 남은 공백이므로 해당 경로의 실험 계획 전에 추가 확인한다.

## 다음 결정

다음 완료 단위는 스프라이트 개념과 표현 단계의 정의다. 원화·프레임·시퀀스·시트·아틀라스·리그·영상과 PNG·WebP 같은 인코딩을 구분하고 공식 근거와 연결한다. 이어 생성 방식과 독립적인 프레임 출력 계약 및 리그 경로의 별도 입력·변환 계약을 검토한다. 엔진·화풍·방향 수의 미결정 사항을 편의상 확정하지 않는다.

계약에는 캔버스·원점·피벗·잘리기 전 크기·트림·패딩·알파·색 공간·방향·프레임 시간·루프·이벤트·상태 전환과 출처 연결을 포함한다. 평가 항목은 형식 Verification·시각 품질 Eval·동작 Eval·실행 성능·제작 비용으로 나누고 미측정과 해당 범위 밖을 명시한다.

그다음 픽스처와 전체 실험 목록의 의존성·우선순위·예산을 정하고 첫 실행 계획을 커밋한다. 모델·제공자·매개변수·기록 생성과 산출물 검사를 연결한 뒤 실제로 실행한다. EPOCA 적응 인지의 기준이 필요한 실험과 형식·성능 실험을 구분해 병목을 줄인다.

현재 기록 규약은 이번 분석에 적용할 수 있었다. 분류 버전은 유지한다. 높은 evidence_level을 모든 주장에 확대하지 않고 본문에서 확인 범위를 나누는 방식이 필요함을 확인했다. 문서·기록·로컬 링크 자동 검사와 별도의 문체·근거 검토를 수행하며, 검사 통과를 도구 실행의 증거로 사용하지 않는다.
