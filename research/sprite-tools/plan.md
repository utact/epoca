## 조사 질문

기존 도구가 어떤 문제를 해결하며, 어떤 기능과 입출력·구현 구조·검증 수단을 제공하는지 확인한다. 후속 개발에서 채택하거나 조합할 구성 요소와 추가 검증이 필요한 질문을 정리한다.

## 범위와 제외

2D 스프라이트의 생성·편집·애니메이션·이미지 처리·패킹·내보내기·재생에 사용하는 오픈소스 도구를 조사한다. 생성형 AI를 사용하는 도구와 사용하지 않는 도구를 모두 포함한다. 각 프로젝트가 해결하는 작업을 먼저 확인하고 담당 기능에 따라 분류한다.

이 조사는 기존 기능과 구현을 확인한다. 생물 분류·생물별 동작 지침·외형 적응을 모든 도구의 필수 기능이나 합격 기준으로 요구하지 않는다. 실제로 해당 기능을 제공하는 프로젝트가 있으면 근거와 함께 기록한다. 우리 기능 가설과 EPOCA 적용 검증은 [2D 스프라이트 개발 계획](../../docs/engineering/sprite-development.md)에서 다룬다.

## 후보 선정

널리 쓰이는 도구와 인기도·유지보수 활동을 확인할 수 있는 저장소부터 찾는다. 검색 날짜·검색어·범위·포함 및 제외 이유를 남긴다. 담당 기능, 실행 가능한 코드·예제·테스트, 코드·모델·에셋의 사용 조건도 확인한다. 스타 수만으로 품질이나 적합성을 판단하지 않는다.

텍스트·참조 이미지 기반 생성, 시트 생성, 영상에서 프레임 추출, 프레임 편집, 리그·파츠 애니메이션, 이미지 처리, 아틀라스 패킹과 재생을 검색 범위로 둔다. 이는 탐색을 위한 작업 분류이며 도구 하나가 모두 제공해야 한다는 뜻은 아니다. 후보 이름과 개수는 검색 결과로 정한다.

## 분석 기준

[기술 조사 및 실험 지침](../../docs/engineering/research.md)에 따라 다음 순서로 분석한다.

1. 프로젝트의 목적·사용자·지원 범위와 범위 밖의 작업을 확인한다.
2. 주요 기능과 입력·중간 표현·출력, 사용자가 준비해야 할 작업을 확인한다. 제작 형식과 실행 형식, 베이크(bake) 등 형식 간 변환 지원도 확인한다.
3. 해당 기능의 실행 경로와 의존성·설치·사용 조건을 확인한다.
4. 안내·검사·실패 처리·수정·테스트의 존재와 실제 연결을 확인한다. AI 작업 환경을 제공하는 부분에는 하네스 역할 분류를 적용하고, 일반 라이브러리에는 해당하는 역할만 기록한다.
5. 제공 기능에 해당하는 출력 형식·알파·크롭·정렬·프레임 순서·재생 시간·품질 및 성능 검사를 확인한다. 문서 설명·코드 확인·실행 결과를 구별한다.
6. 동일 작업을 수행하는 도구끼리 비교하고, 다른 작업을 담당하는 도구는 조합 가능한 구성 요소로 기록한다. 지원 범위 밖의 항목은 해당 없음, 확인하지 못한 항목은 미확인으로 구분한다.

## 진행 순서

1. 후보를 탐색하고 담당 기능별로 분류한다.
2. 확인할 버전을 고정하고 저장소별 분석을 작성한다.
3. 목적·기능·입출력·검증 방식과 근거를 비교 보고서에 정리한다.
4. 재사용 가능한 구성 요소와 추가 확인할 질문을 추린다. 후속 요구사항 정의·벤치마크·가설 검증의 입력으로 넘긴다.

## 완료 조건

선정·제외 이유와 고정 버전의 분석 근거가 있고, 담당 기능별 비교 및 미확인 사항을 조사 보고서에서 확인할 수 있어야 한다. AI 생성 경로뿐 아니라 편집·처리·출력·재생 단계의 조사 범위와 누락도 명시한다. 실행하지 않은 후보의 품질이나 성능은 판정하지 않는다.

현재 후보 탐색은 미착수다. 다음 작업은 1단계의 후보 탐색이며, 자체 도구 개발 여부는 조사와 후속 실험의 근거로 결정한다.
